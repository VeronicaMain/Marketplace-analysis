# Аналитика маркетплейса: метрики, воронка, когорты и LTV продавцов

## О проекте

Проект на SQL, посвящённый анализу бизнес-метрик маркетплейса: от базовых показателей продаж до когортного анализа удержания продавцов и расчёта LTV. В отличие от первого проекта (анализ оттока клиентов банка), здесь в фокусе не отдельный клиент, а продавец как ключевая бизнес-единица — стандартный подход для маркетплейсов и платформенных бизнесов.

Данные: заказы, детали заказов и лог пользовательских событий (view/cart/purchase) внутриплатформенного маркетплейса.

## Методология

### 1. Ежедневный дашборд ключевых метрик

Базовый обзор бизнеса по дням: GMV (оборот), количество заказов, средний чек (AOV), число уникальных покупателей (DAC), частота покупок, средняя стоимость товара (AIV) и среднее число товаров в заказе.

Полный запрос: `queries/daily_metrics.sql`

### 2. Воронка "создан → оплачен"

Не все созданные заказы доходят до оплаты. Отдельно считается количество заказов, зависших между `date_created` и `date_paid`, а также GMV и маржа (через `commission`) именно по оплаченным заказам — как за период, так и в разбивке по дням с расчётом маржи на заказ.

Полный запрос: `queries/funnel_created_paid.sql`

### 3. Сегментация по категориям

GMV в разбивке по `category_name` за выбранный период — показывает, какие товарные категории дают основной оборот.

Полный запрос: `queries/segmentation.sql`

### 4. Событийная воронка (view → cart → purchase)

В отличие от предыдущих разделов, здесь источник данных — не таблица заказов, а сырой лог пользовательских событий. Через условный подсчёт уникальных пользователей (`COUNT(DISTINCT CASE WHEN event_type = ... THEN user_id END)`) строится дневная воронка: сессии, DAU, пользователи с просмотром/корзиной/покупкой. Отдельно считаются MAU и число заказов через составной ключ `(user_id, event_time)`, а также конверсия сессий в покупку по дням.

Полный запрос: `queries/event_funnel.sql`

### 5. Когортный анализ и retention продавцов

Продавцы группируются в когорты по месяцу первой оплаченной продажи (`date_paid`). Для каждой когорты по месяцам показано, сколько продавцов из исходной когорты остаются активными (`retention = sellers_paid / cohort_size`), а также GMV, маржа и ARPPS (средняя выручка на продавца) помесячно.

Полный запрос: `queries/cohort_retention.sql`

### 6. LTV по когортам (6 месяцев)

Наиболее комплексный запрос проекта — цепочка из четырёх CTE: определение когорты продавца → все его продажи → фильтрация продаж за первые 6 месяцев с момента первой оплаты → агрегация маржи на продавца по когортам. Результат — LTV (совокупная маржа за 6 месяцев на одного продавца) по каждой когорте, что позволяет сравнить, какие когорты продавцов оказались наиболее ценными для платформы.

Полный запрос: `queries/ltv_by_cohort.sql`

### 7. Динамика маржи неделя к неделе

Через оконную функцию `LAG() OVER (ORDER BY w_date)` считается маржа предыдущей недели для каждой строки, а затем — процентный рост/падение маржи от недели к неделе.

Полный запрос: `queries/margin_growth.sql`

## Технологии

PostgreSQL · SQL (CTE, множественные JOIN, оконные функции LAG/ROW_NUMBER, условная агрегация через CASE WHEN внутри COUNT DISTINCT)
